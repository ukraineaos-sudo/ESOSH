ТЗ: универсальный генератор сертификатов ESOSH
Нужно реализовать универсальный шаблон PDF-сертификата для обучающих курсов The European Society of Occupational Safety and Health / Європейське співтовариство з охорони праці.
Приложенный PDF использовать только как визуальный референс. Текст из старого сертификата не копировать как содержание конкретного курса.
1. Общая идея
Сертификат формируется после успешного прохождения пользователем конкретного курса.
Один и тот же визуальный шаблон должен использоваться для разных курсов. Содержание сертификата подставляется из данных курса и записи о прохождении.
Пользователь перед первым скачиванием вводит только:
Им’я та прізвище / Full name
Все остальные данные формируются системой.
После первой выдачи сертификата его данные должны быть зафиксированы в базе. Повторное скачивание сертификата не должно создавать новый номер или новую дату.
2. Формат документа
Создавать одностраничный PDF.
Ориентация: горизонтальная, landscape.
Предпочтительный формат: A4 landscape.
Пропорции: примерно как у предоставленного образца.
Сертификат должен хорошо выглядеть:
- на экране;
- при скачивании PDF;
- при печати на A4 без обрезания важных элементов.
Не использовать HTML-страницу, снятую скриншотом. Желательно генерировать нормальный PDF либо использовать HTML/CSS-шаблон с печатной геометрией, гарантирующий одинаковый результат.
3. Визуальный стиль
Основной стиль взять из приложенного сертификата.
Цвета
Основной корпоративный цвет — тёмно-синий / navy.
Дополнительный акцент — жёлтый, соответствующий украинской цветовой паре и существующему дизайну ESOSH.
Фон сертификата — белый или очень светлый нейтральный.
Не использовать градиенты, тени, стеклянные карточки или современную web-стилистику. Это официальный документ.
4. Внешняя рамка
По всему периметру документа должна проходить толстая тёмно-синяя прямоугольная рамка, как в исходном сертификате.
Рамка:
- одинаковой толщины по четырём сторонам;
- находится с небольшим отступом от края страницы;
- визуально формирует официальный бланк;
- не пересекается с основным текстом.
Ориентировочно:
- внешний отступ: 12–18 мм;
- толщина рамки: 4–6 мм.
Внутри рамки оставить достаточно воздуха.
5. Верхний блок — логотип
В самом верху сертификата по центру располагается логотип ESOSH.
Логотип будет передан отдельным PNG/SVG-файлом.
Требования:
- сохранить пропорции;
- не растягивать;
- ширина ориентировочно 70–90 мм либо визуально около 12–16 % ширины листа;
- расположен строго по горизонтальному центру.
Никакой рамки или подложки вокруг логотипа не требуется.
6. Название организации
Под логотипом разместить две строки либо одну аккуратную двуязычную композицию:
THE EUROPEAN SOCIETY OF OCCUPATIONAL SAFETY AND HEALTH
ЄВРОПЕЙСЬКЕ СПІВТОВАРИСТВО З ОХОРОНИ ПРАЦІ
Стиль:
- тёмно-синий;
- полужирный;
- значительно меньше главного заголовка сертификата;
- центрирование.
Это постоянный текст шаблона.
7. Главный заголовок
Ниже крупно:
CERTIFICATE OF COMPLETION
СЕРТИФІКАТ ПРО ПРОХОДЖЕННЯ КУРСУ
Можно разместить одной двуязычной строкой через /, если это визуально лучше:
CERTIFICATE OF COMPLETION / СЕРТИФІКАТ ПРО ПРОХОДЖЕННЯ КУРСУ
Главный заголовок должен быть одним из наиболее заметных элементов сертификата.
Цвет — тёмно-синий.
8. Вводный текст
Ниже небольшим размером:
This is to certify that / Цим засвідчується, що
Это постоянный текст.
9. ФИО участника
Следующий элемент — один из главных визуальных акцентов сертификата.
Динамическое поле:
{{participantName}}
Например:
Олексій Некрасов
ФИО:
- крупный размер;
- тёмно-синий;
- по центру;
- допускается тонкая горизонтальная линия под именем;
- должно автоматически уменьшаться по размеру, если имя очень длинное;
- запрещать перенос ФИО на три строки;
- предпочтительно одна строка, максимум две.
ФИО вводится самим пользователем перед первой генерацией сертификата.
Перед кнопкой генерации показать:
Ім’я та прізвище для сертифіката
и подсказку:
Введіть ім’я та прізвище так, як вони мають бути зазначені у сертифікаті.
После подтверждения и выпуска сертификата сохранить это значение в базе.
10. Подтверждающая фраза
После имени:
has successfully completed the training course and passed the final assessment
успішно пройшов(ла) навчальний курс та склав(ла) підсумкове оцінювання
Постоянный текст шаблона.
Размер меньше названия курса и имени участника.
11. Название курса
Следующий крупный центральный блок.
Динамические поля:
{{courseTitleUk}}
{{courseTitleEn}}
Например:
ОЦІНЮВАННЯ РИЗИКІВ: ВСТУПНИЙ КУРС
RISK ASSESSMENT: AWARENESS COURSE
Название курса не генерируется AI.
Оно автоматически подтягивается из данных того курса, который пользователь прошёл.
Название должно:
- быть выделено полужирным;
- располагаться по центру;
- украинское название сверху;
- английское снизу;
- автоматически адаптировать размер шрифта при длинном названии.
12. Длительность
Под названием курса:
Тривалість / Duration: {{durationUk}} / {{durationEn}}
Для текущего проекта:
Тривалість / Duration: 30 хвилин / 30 minutes
Важно: длительность не берётся из админки курса.
Она передаётся в конфигурации сертификата или отдельной настройкой, задаваемой разработчиком/администратором для конкретного шаблона курса.
То есть сертификат должен принимать значение duration как отдельный параметр.
13. Содержание курса / модули
Следующий блок:
Зміст курсу / Course content
Под ним динамический список модулей.
Данные автоматически берутся из реальных модулей курса.
Формат каждого пункта:
1. Українська назва модуля
English module title
2. Українська назва модуля
English module title
и т. д.
Для трёх модулей это должно выглядеть компактно и аккуратно.
Название украинского модуля можно делать полужирным, английский вариант — обычным или чуть меньшим.
Система не должна генерировать названия модулей самостоятельно.
Использовать именно названия из структуры курса.
Важно по адаптивности
Количество модулей потенциально может отличаться между курсами.
Поэтому блок должен поддерживать хотя бы 1–6 модулей.
Если модулей больше либо названия длиннее:
- сначала немного уменьшать вертикальные интервалы;
- затем умеренно уменьшать размер шрифта;
- не допускать выхода текста за нижнюю служебную область.
14. Нижняя служебная область
В нижней части сертификата разместить три логических блока.
Слева
Дата завершення курсу / Completion date:
{{completionDate}}
Дата берётся с сервера, а не из браузера пользователя.
Дата фиксируется в момент успешного завершения курса или выдачи сертификата согласно логике системы.
После создания сертификата дата не изменяется при повторном скачивании.
Формат желательно:
07.10.2026
или при необходимости:
07 October 2026 / 07 жовтня 2026
Но для первой версии достаточно DD.MM.YYYY.
По центру или немного левее центра
Номер сертифіката / Certificate No.:
{{certificateNumber}}
Формат номера:
ESOSH-RA-2026-000483
Общая структура:
ESOSH-{COURSE_CODE}-{YEAR}-{SEQUENTIAL_NUMBER}
Пример:
- ESOSH-RA-2026-000483
- ESOSH-CS-2026-000484
Где:
- ESOSH — постоянный префикс;
- COURSE_CODE — короткий код конкретного курса;
- YEAR — год выдачи;
- последние шесть цифр — уникальный последовательный номер.
Номер должен генерироваться только один раз.
15. Подпись
В правой нижней части должна находиться подпись председателя ESOSH.
Подпись будет передана отдельным файлом:
signature-olha-bohdanova.png
Формат:
- PNG;
- прозрачный фон;
- высокое разрешение.
Изображение подписи позиционировать в заранее установленной области.
Не хранить подпись как base64 непосредственно в коде, если можно использовать ассет проекта.
Не растягивать и не искажать.
Под подписью:
Голова правління ESOSH / Chairperson of ESOSH
Ольга Богданова / Olha Bohdanova
Либо имя можно разместить непосредственно рядом с линией подписи — выбрать вариант, наиболее близкий визуальному референсу.
Важно: изображение подписи должно накладываться поверх области подписи, а не быть частью фонового изображения сертификата.
Таким образом позднее подпись можно заменить без переделки всего шаблона.
16. Нижний декоративный элемент
В оригинальном визуальном референсе нижняя часть состоит из двух больших диагональных геометрических областей:
- тёмно-синяя;
- ярко-жёлтая.
Сохранить эту идею.
Они должны занимать только нижнюю декоративную область и не перекрывать дату, номер сертификата или подпись.
Геометрия:
- простая;
- плоская;
- без теней;
- без градиентов;
- диагональные линии сходятся примерно в центральной нижней части.
Важно: удалить любые элементы сторонних сервисов вроде:
Made for free with Certify'em
В новом сертификате таких элементов быть не должно. В старом PDF этот водяной знак действительно присутствует.     Шаблон_сертифікату_оцінка_ризик…
17. Иерархия элементов
Визуальный приоритет сверху вниз должен быть таким:
1. Логотип ESOSH
↓
2. Название организации
↓
3. CERTIFICATE OF COMPLETION
↓
4. ФИО участника
↓
5. Название курса
↓
6. Длительность
↓
7. Содержание курса / модули
↓
8. Дата + номер + подпись
↓
9. Сине-жёлтый декоративный низ
Не перегружать документ.
Белое пространство является частью дизайна.

19. Что хранить в базе
Поскольку сертификат является официальным подтверждением прохождения курса, создать отдельную сущность сертификата.
Минимально сохранить:
certificateId
memberId
courseId
participantName
courseTitleUk
courseTitleEn
courseCode
duration
completionDate
certificateNumber
issuedAt

Также желательно сохранить snapshot списка модулей:
certificateModules

Почему snapshot важен: если через год название курса или модуля изменят в админке, уже выданный сертификат не должен задним числом менять содержание.
20. Связь с участником
Система должна однозначно знать:
какой зарегистрированный участник → какой курс → когда завершил → какой сертификат получил.
Для одной комбинации:
memberId + courseId
должен существовать один действующий сертификат, если бизнес-логика не предусматривает повторное прохождение курса.
Повторное нажатие «Скачать сертификат»:
- не создаёт новую запись;
- не создаёт новый номер;
- не меняет дату;
- не спрашивает повторно ФИО, если сертификат уже выпущен;
- отдаёт существующий сертификат либо регенерирует идентичный PDF по сохранённым данным.
21. Логика выпуска
После успешного прохождения курса:
1. Проверить, действительно ли участник завершил все обязательные модули/тесты.
2. Показать кнопку:
Отримати сертифікат
3. Если сертификат ещё не выпускался — запросить ФИО.
4. Показать ФИО пользователю перед окончательным подтверждением:
Сертифікат буде видано на ім’я:
Олексій Некрасов

Кнопки:
Назад / Виправити
Підтвердити та сформувати
5. Сервер:
- получает серверную дату;
- создаёт уникальный номер;
- фиксирует запись сертификата в БД;
- генерирует PDF.
6. Пользователь получает:
Завантажити сертифікат PDF
22. Важное требование к номеру
Нельзя определять следующий номер на клиенте.
Генерация должна происходить атомарно на сервере/в базе, чтобы два пользователя, одновременно завершившие курс, не получили одинаковый номер.
Уникальность certificateNumber закрепить constraint/index в БД.
23. Ассеты
Позднее будут переданы:
/assets/certificate/esosh-logo.png
/assets/certificate/signature-olha-bohdanova.png

Пока этих файлов нет, заложить для них два placeholder-контейнера:
ESOSH LOGO
и
SIGNATURE
чтобы финальная геометрия сертификата уже была построена и после добавления файлов ничего не пришлось передвигать.
24. Главное дизайнерское требование
Это должен выглядеть как официальный европейский учебный сертификат, а не как web-карточка.
Не использовать:
- карточки с rounded corners;
- UI-кнопки внутри PDF;
- стеклянные панели;
- тени;
- декоративные иконки возле каждого пункта;
- лишние изображения;
- визуальные эффекты сайта.
Основная эстетика:
чистый белый документ + navy typography + логотип ESOSH + строгая симметрия + небольшие жёлтые акценты + подпись + официальный номер.
