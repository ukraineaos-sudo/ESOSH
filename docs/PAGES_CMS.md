# CMS «Сторінки» — чому приховано і що потрібно для увімкнення

Статус: **вимкнено в меню** (`AdminShell` не показує пункт; `/admin/content/pages` → redirect на `/admin`).

Код кімнати збережено: `PagesManager`, закоментований UI у `src/app/admin/content/pages/page.tsx`, API `/api/admin/pages`.

## Чому не вмикаємо зараз

1. Редактор блоків (hero / richText / cards…) **не WYSIWYG** — незручний для редакторів без ТЗ.
2. Немає імпорту legacy-сторінок з `src/content/pages/{uk,en}/**` у `pages` (на відміну від новин).
3. Публічний dual-read уже є (`getPage` → CMS → TSX), але без імпорту кімната показує «без CMS» майже для всього каталогу — це плутає («legacy island»).
4. Новини (Phase A–C) уже закривають головний контентний контур сайту.

## Мінімум перед повторним увімкненням

1. **WYSIWYG або спрощений редактор** для `richText` (як у новинах) + зрозумілі людські підписи блоків.
2. **Імпорт / стратегія** для ключових сторінок (хоча б home, about, businesses) або явний режим «лише нові CMS-сторінки».
3. **Копірайт і UX українською** без жаргону dual-read / legacy у інтерфейсі.
4. **Короткий smoke**: publish → публічна сторінка показує CMS; unpublish → знову TSX fallback.
5. Розкоментувати nav у `AdminShell` + повернути UI в `content/pages/page.tsx`.

Див. також `CODE_MAP.md` (розділ Admin / відомі прогалини).
